# HolaHola - Interactive Language Tutor

## Overview
HolaHola is an AI-powered language learning application offering interactive conversation practice, vocabulary building, and grammar exercises across ten languages, adhering to ACTFL standards. Its vision is to be a leading AI-driven educational platform, leveraging advanced technology and pedagogical innovation to capture significant market potential in personalized language acquisition. The platform also differentiates itself by presenting multiple perspectives on contested topics in subjects like Biology and US History, providing balanced content for homeschool families.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture
The frontend uses React, TypeScript (Vite), Shadcn/ui (Radix UI), and Tailwind CSS for a mobile-first, responsive Material Design with light/dark modes and PWA capabilities. Wouter handles routing, and React Context with TanStack Query manages state. The backend is an Express.js (Node.js) server with TypeScript, providing a RESTful API and Drizzle ORM for PostgreSQL.

A Unified TutorOrchestrator Architecture centralizes AI interactions through Daniela, incorporating the Hive Collaboration System and Student Learning Service. Key data models include Users, Conversations, VocabularyWords, and UserProgress. The system features an "Neural Network for Pedagogical Strategies," AI-powered conversation tagging, a Syllabus-Aware Competency System, and centralized Role-Based Access Control (RBAC). It supports pre-built syllabi across 10 languages and unified ACTFL assessment. A Voice Diagnostics System provides TTS observability.

The Editor Intelligence System offers cross-session memory for the Replit Agent. The Alden Session Startup Protocol loads curated insights and recent conversation summaries. The Unified Daniela Context Service ensures a consistent "One Daniela always" experience. Other components include an Observation Summarization System, Daniela Content Growth System, Voice Intelligence System, a Hybrid Memory Architecture, and a Message Checkpointing System. The ACTION_TRIGGERS Command Parsing System processes Daniela's tags for backend commands.

The Fluency Wiring System connects ACTFL Can-Do statements to lessons. An AI Lesson Generation System creates structured lesson drafts, processed by a Lesson Publishing Service. The Drill System supports multiple interactive drill types, and the Practice Explorer System enables self-directed drill practice. An Interactive Textbook serves as a visual quick-reference. The Gauntlet Runner Identity Stress Test System validates Daniela's voice identity.

The TTS provider strategy supports Google Cloud TTS (Chirp 3 HD) as primary, with Cartesia (Sonic-3), ElevenLabs (Flash v2.5), and Gemini (2.5 Flash Live) as alternatives. TTS dispatch is centralized via `tts-provider-adapter.ts` using a unified `TTSStreamingProvider` interface, managing batch vs. progressive streaming. WebSocket warm-up and an app-level heartbeat ensure connection reliability. The Voice Context Pipeline (`voice-context-pipeline.ts`) centralizes shared context-building logic for PTT and OpenMic voice paths.

A "Smart Fat Context" memory architecture preloads the student's complete profile, learned vocabulary, and recent conversations into Gemini's context window at session start to ensure rich, personalized interactions.

The `streaming-voice-orchestrator.ts` has been refactored, delegating TTS synthesis, audio streaming, and provider-specific dispatch to `tts-dispatcher.ts`. Native function call handling is managed by `native-fc-handlers.ts`, and background enrichment tasks are handled by `post-response-enrichment.ts`.

The interactive textbook is accessible via `/interactive-textbook`. Subject tutors for Biology (`/biology`) and History (`/history-tutor`) are live with specific personas. Reading modules are pre-generated, permanently cached textbook documents, generated via a four-stage pipeline: OpenStax content fetching, structured JSON generation, academic citation enrichment, and quantitative claim verification, stored in the `reading_modules` table. Student reading progress is tracked in `reading_module_views`, and a Progress Report (`/progress-report`) provides summaries and quizzes.

The Class Creation Hub (`/teacher/create-class`) now supports creating Language Classes, Academic Subject Classes linked to OpenStax textbooks, or starting from scratch. Academic classes are linked to `subject_syllabi` and identified by `is_academic_class`.

The Team Room (`/team-room`) is an internal collaboration space for David and the full AI team. Features:
- **3-panel layout**: participants (left), discussion thread (center), Express Lane analysis panel (right)
- **6 core participants + guest tutors**: David (amber), Alden (blue, Dev Steward via Claude), Daniela (purple, Curriculum Advisor via Gemini), Sofia (emerald, Tech Health via Gemini), Lyra (pink, Learning Analyst via Gemini), Wren (sky, Architect via Gemini); guest tutors can be invited from tutor_voices table and disconnected per-session
- **Smart hand-raise logic**: all AI participants (core + guests) evaluate each message in parallel; only those with genuine contributions respond. Hand raises show visually with an animated icon and tooltip explaining reasoning
- **@mentions**: type `@name` in chat or click the visible @ button next to any AI participant to summon them directly; supports both core and guest tutor names
- **Guest tutor invite/disconnect**: `POST /api/team-room/sessions/:id/invite` and `/disconnect` routes; guests stored in room metadata JSON; invited tutors evaluate via Gemini with their persona context
- **PTT voice input**: Web Speech API PTT button; AI responses played back via `/api/team-room/voice/tts` using distinct Neural2 voices per participant
- **Shared canvas artifacts**: Alden generates structured artifacts (plans, tables, code blocks, insights, decisions) stored in `room_artifacts` and displayed as interactive cards in the Express Lane
- **Cross-session continuity**: on session close, Alden generates an enriched summary (decisions, action items, momentum note) stored in `room_session_summaries` and injected as a "Previously in this room..." banner at next session start; summaries are also bridged to the Express Lane via `hiveBridgeService.notifyHive()`
- **Action items tracker**: session close summaries extract key decisions and action items; displayed as a checklist in the summary banner; accessible via `GET /api/team-room/action-items/:topic`
- **Session replay**: closed sessions open in read-only mode with full message history (200 msgs), summary banner with action items, artifacts in Express Lane, and voice replay buttons on AI messages; status badge shows "Replay" instead of "Live"
- **CAP-001 — Proactive worker posting**: When a Team Room session is active, background workers (Wren security audit, Lyra analytics) automatically post a natural-language summary to the room when they find significant issues (HIGH/CRITICAL severity or `needsReview` flags). Messages are generated by Gemini in each participant's persona voice, saved to `room_voice_messages`, and emitted over WebSocket. Shared utility: `server/services/team-room-proactive-poster.ts`. Manual test trigger: `POST /api/team-room/test-proactive-post`.
- **CAP-002 — Alden weekly digest**: Alden runs a weekly initiative tracker (`server/services/alden-digest-worker.ts`) that gathers data from Wren's security stats, Lyra's analytics stats, Sofia's pending issue queue, and recent Express Lane activity; passes it to Claude (Opus) to generate a 3-5 item prioritized agenda in Alden's voice; posts to active Team Room. Fires 3 minutes after startup then every 7 days. Manual trigger: `POST /api/team-room/trigger-weekly-digest`. Alden proposes — David decides.
- **CAP-003 — Wren auto-patch**: After each security audit, `server/services/wren-auto-patch-service.ts` reviews every finding in full source context (±18 lines) via Gemini Flash. Outcomes: (1) Patched — applies code fix directly to file, posts before/after diff to Express Lane; (2) Dismissed false positive — registers in in-memory registry, documents reasoning; (3) Escalated — real issue that needs discussion stays in queue. Criteria: ≤5 line change, no new deps, localized, reversible. False positives are cached for the server's lifetime. Manual trigger: `POST /api/team-room/trigger-auto-patch`. Team Room alert filter also updated to exclude known false positives.
- **CAP-004 — Lyra content trigger (ACTFL auto-assignment)**: `server/services/lyra-content-trigger-service.ts` — after each Lyra analytics run, lessons with missing ACTFL proficiency alignment are automatically assigned levels via Gemini Flash inference. The assignment is based on lesson name, type (drill, conversation, grammar, etc.), and language. Results written directly to `curriculum_lessons.actfl_level`. A detailed report is posted to Lyra's Express Lane session listing all assignments and rationale. Integrated into `lyra-analytics-worker.ts` after each analysis. Manual trigger: `POST /api/team-room/trigger-content-fix`.
- **CAP-005 — Sofia issue cleanup**: `server/services/sofia-issue-cleanup-worker.ts` — weekly worker that reviews pending issues older than 30 days, groups by issue type, and uses Gemini Flash (with current system health context) to decide which types are historical artifacts that can be auto-resolved. Resolved issues are stamped in `founder_notes` with reason and resolution date. Conservative approach — retained issues stay pending for founder review. Posts summary to Sofia's Express Lane session; posts brief to Team Room if any issues were resolved. Fires 90 seconds after startup, then every 7 days (3-day dedup guard). Manual trigger: `POST /api/team-room/trigger-sofia-cleanup`.
- **CAP-006 — Alden memory-driven check-ins**: `server/services/alden-checkin-service.ts` — after each Lyra analysis run, Alden loads David's top 100 relevant memory facts (preference, goal, work, notable_mention types from `learner_personal_facts` for student_id '49847136') plus architectural insights. Gemini Flash cross-references against Lyra's significant findings (HIGH/CRITICAL/needsReview) and rates confidence 1-10. Only fires check-in if confidence >= 6. Posts a short memory-anchored message to both Team Room and Alden's Express Lane session with the specific memory anchor cited. 4-hour minimum gap prevents spam. Integrated into `lyra-analytics-worker.ts`. Manual trigger: `POST /api/team-room/trigger-alden-checkin` with `{ findings: [...] }`.
- **CAP-007 — Alden as architectural code reviewer**: `server/services/alden-code-review-service.ts` — Wren now **proposes** fixes (stored in `proposed_code_changes` table, status: pending_review) instead of applying them directly. After each audit, `runReviewQueue()` is called — Alden reviews each proposal using Claude Opus + `editorInsights` memory. Authority boundary: autonomously approves ≤15 lines, bug fixes, security patches (no new deps/schema/auth/payment). Sends back `revised` with specific feedback if approach is wrong. Escalates to David via Team Room for architectural changes. On approval: patches the file + syncs to GitHub with `[AUTO-FIX]` commit. Weekly digest includes code review stats (applied, revised, escalated by name). Trigger routes: `POST /api/team-room/trigger-code-review`, `GET /api/team-room/proposed-changes`.
- **CAP-008 — Real-time collaborative building**: `server/services/alden-build-service.ts` — when David sends a feature request in the Team Room, the build pipeline fires: (1) Gemini Flash classifies build intent, (2) Alden acks immediately, (3) code context loaded from relevant files with line numbers, (4) Daniela posts her perspective as co-founder and AI-who-uses-it (function call design, ROI, student experience), (5) Claude Opus plans with exact file changes using Daniela's input, (6) plan posted as Artifact, (7) changes applied to disk, (8) GitHub synced with `[FEATURE]` commit, (9) completion report with what to test. Non-build messages (questions, discussion) bypass the pipeline and use normal multi-agent evaluation. HTTP response returned immediately; all pipeline updates arrive via WebSocket.
- **CAP-009 — Daniela self-critique from real session data**: `server/services/daniela-self-critique-service.ts` — when David asks Daniela to review sessions ("Daniela, review my last Spanish session"), Daniela-founder analyzes real `conversations` + `messages` (with per-turn `performanceScore`) + `tutorSessions` (goals, tutorNotes, topicsCovered) + `voiceSessions` (speaking ratio) data. Gemini Flash runs a structured self-critique comparing actual teaching against student goals, performance trends, speaking ratios, scaffolding patterns, and comprehension checks. Output: voice summary to Team Room + detailed Express Lane critique + `daniela_self_critique` artifact with specific problem moments, pattern analysis, action items for Alden, and personal tutor-persona notes. Sessions found by `ownerEmail` (cross-env safe). Supports "my sessions" or "Hadassah's sessions" via named target. Fires as async pipeline identical to CAP-008 build pipeline pattern.
