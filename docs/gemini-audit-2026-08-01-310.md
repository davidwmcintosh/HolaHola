# Gemini Audit — Task #310 (Wire activePatternSignals into text-mode session handler)
**Date:** 2026-08-01  
**Auditor:** Gemini 3-flash-preview (2 rounds)  
**Triggered by:** Post-merge Gemini gate (daniela-caller.ts changed)

## What was reviewed
Task #310 extended pattern signal injection — previously only wired for GL voice sessions and the `runDanielaFCLoop` entrypoint — to the `callDaniela` wrapper and `study-mode-service.ts`. Goal: when a student switches from voice to study mode, Daniela keeps her active grammar pattern map without requiring a StreamingSession object.

## Round 1 — Bug found: double injection on tools path

Gemini identified that `callDaniela` was injecting the pattern note into `systemPrompt` *and* then passing `activePatternSignals` to `callDanielaWithTools → runDanielaFCLoop`, which injects it again via `effectiveSystemPrompt`. Double injection on the `enableTools=true` path. Risk: instruction fatigue / over-fixation on pattern signals.

**Fix applied:** `callDaniela` now only injects when `!enableTools`. The tools path passes systemPrompt clean and lets `runDanielaFCLoop` be the single injection point.

Gemini also flagged hardcoded `'spanish'` in `study-mode-service.ts` as technical debt. Fixed by extracting to `STUDY_MODE_LANGUAGE = 'spanish' as const` with upgrade-path comment.

## Round 2 — Verdict: APPROVED, Audit Closed

> "The code is ready for production. Status: Audit Closed. Fixes Verified."

Gemini confirmed:
- Double injection eliminated: simple path injects once, tools path delegates to `runDanielaFCLoop`
- Language constant correctly encapsulates the current limitation
- Defensive formatting (`endsWith('\n')` + `trimStart()`) is consistent and correct

Minor standing note (non-blocking): DB writer for pattern signals must stay unit-tested on bullet format (`-` or `•`) — if it drifts, `formatActivePatternSignalNote` silently returns empty. Tests should be in CI.
