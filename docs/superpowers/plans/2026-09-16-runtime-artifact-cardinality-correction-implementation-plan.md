# Runtime Artifact Cardinality Correction Implementation Plan

**Date:** September 16, 2026
**Design:** `docs/superpowers/specs/2026-09-14-coordinator-v2-windows-runtime-bootstrap-design.md`

## Goal

Correct the runtime artifact manifest so distinct fixed destinations may
reference one immutable content-addressed object without weakening destination
uniqueness, byte integrity, append-only evidence, source authority, or runtime
publication rollback.

## Constraints

- Remove only the uniqueness of `(runtime_release_id, object_key)`.
- Retain uniqueness of `(runtime_release_id, fixed_destination)`.
- Retain every role, digest, length, object-key, foreign-key, and append-only
  database constraint.
- Retain publication-time and authenticated-download object reinspection.
- Do not rewrite existing rows or create object-store aliases.
- Do not publish a runtime release, create Windows authority, initialize
  Windows, or invoke the coordinator as part of this correction.
- Apply no schema change to shared Neon before the disposable branch gate
  reports `READY_TO_PROMOTE`.

## Step 1: Correct the schema source of truth

### File

- `shared/schema.ts`

### Work

Remove only `uq_coordination_v2_runtime_artifact_object` from the runtime
artifact table definition. Leave destination uniqueness and all checks
unchanged.

### Gate

- The diff contains no other schema change.

## Step 2: Generate and review the migration

### Files

- the matching files under `migrations/meta/`

### Work

Generate the migration from the schema source. Review the SQL and metadata
before any database operation.

### Gate

- SQL drops only `uq_coordination_v2_runtime_artifact_object`.
- SQL performs no table rewrite, row mutation, backfill, or unrelated DDL.
- Prior migrations remain unchanged.

## Step 3: Add focused PostgreSQL regression proof

### File

- `server/scripts/test-coordination-v2-runtime-bootstrap-postgres.test.ts`

### Work

Extend the existing disposable-database transaction test to prove:

1. two distinct fixed destinations can share one object key;
2. duplicate fixed destinations still fail with SQLSTATE `23505`;
3. artifact update and delete rejection still pass;
4. the existing invalid-role, invalid-digest, lineage, and rollback checks
   remain green.

### Gate

- The focused test fails against the old schema and passes with the generated
  migration.
- Test writes occur only against a verified disposable database.
