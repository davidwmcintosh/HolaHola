# Gemini Audit — Task #358 (PTT + OpenMic undefined-sentinel fetch-error guard)
**Date:** 2026-08-01  
**Auditor:** Gemini 3-flash-preview  
**Triggered by:** Post-merge Gemini gate (streaming-voice-orchestrator.ts touched)

## What was reviewed
Task #358 ported the null-guard fix from `native-fc-handlers.ts` to the two remaining call sites in `streaming-voice-orchestrator.ts`: the PTT path (~line 3328) and the OpenMic path (~line 6795).

**Old pattern (both sites):**
```ts
const refreshed = await fetchPatternSignalContext(userId, language).catch(() => null);
session.activePatternSignals = refreshed;  // error → null → wipes live wobble
```

**New pattern (both sites):**
```ts
const refreshed = await fetchPatternSignalContext(userId, language).catch((): undefined => {
  console.warn('[PatternSignal] ... preserving existing activePatternSignals ...');
  return undefined;
});
if (refreshed !== undefined) {
  session.activePatternSignals = refreshed;
}
```

Three-way sentinel: `null` = intentional clear (all resolved stable), `undefined` = fetch threw (preserve stale), `string` = fresh signal (replace).

## Gemini verdict: APPROVED

> "This is a solid, targeted fix. Porting the logic from native-fc-handlers.ts ensures consistency across the orchestrator's different input modes (PTT vs. OpenMic)."

- Guard is correct: null still clears, undefined preserves, assignment only fires when `!== undefined`.
- Type-safe: `.catch((): undefined => undefined)` narrows type correctly; `if (refreshed !== undefined)` block sees `string | null` only.
- Consistent with existing RECORD_PATTERN_SIGNAL fix in native-fc-handlers.ts.

No outstanding concerns.
