A few things worth deciding deliberately as part of the migration, since they don't fall out of the code automatically:

Replit Auth (OIDC). Login is tied to Replit's domain. That's fine for production, but local dev sessions (like this one) likely can't fully authenticate against it — expect to hit that wall if you try to test authenticated flows outside Replit.
Secrets duplication. Replit's userenv secrets (.replit) and its integrations (Stripe, object storage, etc.) will need an equivalent story for wherever development now happens, so local .env doesn't drift from what's configured on Replit.
