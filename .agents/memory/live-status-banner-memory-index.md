Session-start protocol compliance (reading `.local/stale-channel-alert.md` and `.local/episode-capture-status.md` before the first output) depends on active discipline — neither file is auto-injected into a hat's context. `computeLiveStatusBanner()` in `server/services/agent-memory-core.ts` closes that gap by reading both files and folding a short headline into the generated `MEMORY.md` index itself, which every hat receives on every turn without having to remember to look elsewhere.

**Why:** MEMORY.md is the one artifact guaranteed to reach context every turn. Any other enforcement point (a new trigger file, a chat-injected reminder) still requires the same active discipline that caused the original gap. See [session-start-skip-pattern.md](session-start-skip-pattern.md) for the failure mode this is the structural fix for.

The banner is recomputed on every DB-triggered index regeneration (`writeMemoryIndexFile()`, called from `addEntry`/`editEntry`/`removeEntry`/`regenerateAll`) and additionally triggered fire-and-forget via `refreshMemoryIndexBestEffort()` from the actual write/clear call sites of the underlying live-state files (`agent-session-autosave.ts`'s stale-channel-alert write/clear, `capture-watchdog.ts`'s `refreshStaleChannelAlert()`), so the banner updates immediately rather than waiting for the next unrelated CLI write to happen to pick it up.

**Gotcha — three writers phrase the same alert differently:** `agent-session-autosave.ts` has two separate code paths that write `.local/stale-channel-alert.md` (the main worker cycle and `seedStaleChannelAlertAtBoot()`), plus `capture-watchdog.ts`'s independent `refreshStaleChannelAlert()` — and they don't all use the same wording. The main worker cycle writes "channels **have been** silent for 10+ min", while the boot-seed and watchdog paths write "channels silent for 10+ min" (no "have been"). A headline-extraction match on the longer/full phrase would silently miss the main worker cycle's alert — the single most common writer — and fall back to a generic first-non-blank-line match (the "# ⚠️ Inner-Life Channel Alert" heading), losing the actual stale-parts detail. The fix: match on "silent for 10+ min", the substring genuinely common to all three.

**How to apply:** any future live-state file added to this pattern should follow the same shape — read-only, wrap each file read in its own try/catch that swallows ENOENT (missing file is the healthy/expected case, not an error), and short-circuit the whole function to `""` under `AGENT_MEMORY_TEST_FILES_DIR` (the live-state files live under this checkout's real `.local/`, with no parallel scratch location — leaking real workspace state into a hermetic DB test's content-equality assertions would be a silent test-isolation break). When adding a new trigger call site, call `refreshMemoryIndexBestEffort(callerLabel)` right after the write/clear, and check any existing test-path-override variable at that call site first — a test redirecting the file to a scratch path must never also cause a live DB read + write against the real MEMORY.md.
