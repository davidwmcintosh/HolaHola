Rule: A "mutation guard" script (flip a real implementation to a known-bad version, confirm the test suite fails, revert, confirm it passes again) must operate on a private temp-directory copy of the file(s) it needs, never the real tracked file on disk.

**Why:** Any other process that reads, imports, or compiles the real file during the mutation window — a concurrently-running CI batch, a second manual test invocation, another `gate`/branch run sharing the same working tree, or even the dev server picking up a file-watch event — observes the corrupted content and fails with a confusing, unrelated-looking symptom. This was the confirmed root cause of an intermittent "AbsenceHistoryPanel — fetch URL construction" flake that only reproduced inside full CI batches, never standalone: the guard script was mutating the real `client/src/lib/absence-history-panel-logic.ts` in place. Directly reproduced by having a second process read the file mid-mutation; disproved after the fix with a 15-way concurrent stress test showing zero failures.

**How to apply:** Use `server/scripts/filter-url-mutation-fixture.ts`'s `createFilterUrlMutationSandbox()` as the reference pattern (mkdtempSync copy, mutate only the copy, run the test against the copy, clean up in `finally`). A related but distinct antipattern also exists: a script that writes a permanent sibling `*.MUTANT.ts`-style fixture file next to the real source inside a tracked directory (client/src, server/, shared/) and deletes it in `finally` — this avoids corrupting the real file, but still performs an in-tree write that a concurrent scan, watcher, or type-checker can observe mid-run. Both antipatterns are now caught automatically by a static scanner (`server/scripts/scan-source-mutation-writes.test.ts`, wired into the validation suite and CI) that fails on any new write into a tracked source directory not routed through a sandbox helper or an explicit, individually-justified allowlist entry. Fixing the remaining grandfathered real in-place-mutation offenders (as opposed to the safer sibling-mutant-file ones) is tracked as separate follow-up work, not done by the scanner itself.
