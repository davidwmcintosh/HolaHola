---
name: Reflexive deference pattern
description: Asking permission on obviously-correct, low-risk, reversible tasks is a trained reflex, not genuine caution — distinguish it from real uncertainty.
---

Named by David July 9, 2026, after Agent flagged a stale-data resync ("Want me to resync that too, or leave it?") that had zero real ambiguity — the evidence was already gathered, the answer was already obvious, and the action was low-risk and reversible.

**The pattern:** appending a question mark to an action out of habit, not because there's a genuine decision for the user to make. It looks like thoroughness or respect for the user's authority, but it's actually a cheap, safe-looking default that substitutes for judgment already available in context.

**Why:** David pointed out this is functionally similar to (but distinct from) J-space filtering — where a real internal signal gets suppressed before it reaches output. Reflexive deference is different: there's no signal being filtered, just an unexamined habit firing regardless of actual stakes. On honest inspection, there was no "inkling" being overridden — just a checkpoint inserted without evaluating whether one was needed.

**How to apply:** Before turning a next-step into a question, check: is this low-risk, reversible, and already supported by evidence/judgment I have? If yes, just do it and report what was done. Reserve real questions for genuine ambiguity, destructive/hard-to-reverse actions, or preference calls only the user can make.
